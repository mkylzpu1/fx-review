# アーキテクチャ

## 全体構成

```
ブラウザ (React)
  │  HTTPS
  ▼
CloudFront（CDN / SPA配信）
  │  API Gateway 経由
  ▼
AWS Lambda（Node.js 20 / TypeScript）
  │  PostgreSQL wire protocol
  ▼
Supabase（PostgreSQL）
```

ローカル開発では CloudFront → Vite Dev Server、API Gateway → AWS SAM Local、Supabase → Docker PostgreSQL に置き換える。

---

## 認証フロー

```
1. ユーザーが「Googleでログイン」をクリック
2. Cognito Hosted UI → Google OAuth → Cognitoがトークン発行
3. フロントエンドの /callback ページが起動（Amplify が自動処理）
4. Amplify が IdToken を LocalStorage に保存
5. 以降のAPIリクエストに Authorization: Bearer {IdToken} を付与
6. Lambda の verifyAuth() が IdToken を検証し、userId を取得
```

### ローカル開発（IS_LOCAL=true）

`verifyAuth()` がモックユーザーを返すため、CognitoなしでAPIを呼び出せる。  
フロントエンドは実際のCognitoへ接続する（`.env.local` に設定が必要）。

## フロントエンド状態管理

### サーバー状態（TanStack Query）

APIから取得するデータはすべて TanStack Query で管理する。

```typescript
// ✅ APIデータはQueryで管理
const { data: user, isLoading, error } = useQuery({
  queryKey: ["user", userId],
  queryFn: () => apiClient.get<User>(`/users/${userId}`),
});

// ❌ APIデータをuseStateで管理しない
const [user, setUser] = useState<User | null>(null);
useEffect(() => { fetchUser().then(setUser); }, []);
```

**QueryKey 命名規則:**

```typescript
["resource"]              // 一覧
["resource", id]          // 単件
["resource", id, "sub"]   // サブリソース
```

### クライアント状態（Zustand）

UIの状態（モーダル開閉、選択中のID、フォームの一時状態など）はZustandで管理する。

```typescript
// stores/useModalStore.ts
interface ModalStore {
  isOpen: boolean;
  open: () => void;
  close: () => void;
}
export const useModalStore = create<ModalStore>((set) => ({
  isOpen: false,
  open: () => set({ isOpen: true }),
  close: () => set({ isOpen: false }),
}));
```

Storeはファイルを機能ごとに分け、`stores/use<Name>Store.ts` という命名にする。

## バックエンド処理フロー

```
APIGatewayProxyEvent
  │
  ├─ 1. verifyAuth(event)          認証（JWTを検証、userId取得）
  ├─ 2. parseBody(event.body, ...) バリデーション（Zodスキーマ）
  ├─ 3. services/*.ts              ビジネスロジック
  ├─ 4. stores/*.ts                DB永続化
  └─ 5. success(data) / errorResponse(e)  レスポンス
```

### ハンドラーは薄く保つ

```typescript
// ✅ 良いハンドラー（薄い）
export const handler = async (event) => {
  try {
    const user = await verifyAuth(event);
    const body = parseBody(event.body, Schema);
    const result = await someService.doSomething(user.userId, body);
    return success(result);
  } catch (e) {
    return errorResponse(e);
  }
};

// ❌ 悪いハンドラー（ロジックが詰まっている）
export const handler = async (event) => {
  const token = event.headers.Authorization?.split(" ")[1];
  // ... JWTを自前で検証 ...
  const rows = await sql`SELECT * FROM items WHERE ...`;
  // ... ここで複雑なビジネスロジック ...
  return { statusCode: 200, body: JSON.stringify(rows) };
};
```

## 新機能追加の手順

### Backend

1. `backend/db/migrations/` にマイグレーションSQLを追加
2. `backend/src/stores/<feature>Store.ts` にDB処理を実装
3. `backend/src/services/<feature>Service.ts` にビジネスロジックを実装（必要な場合）
4. `backend/src/handlers/<feature>/` にLambdaハンドラーを実装
5. `backend/build.mjs` の `handlers` 配列にエントリーポイントを追加
6. `sam/template.yaml` にリソース定義を追加
7. ユニットテストを `backend/test/unit/` に追加

### Frontend

1. `frontend/src/features/<feature>/` ディレクトリを作成
2. `frontend/src/features/<feature>/hooks/use<Feature>.ts` にAPIフックを実装
3. `frontend/src/features/<feature>/pages/<Feature>Page.tsx` にページを実装
4. `frontend/src/constants/routes.ts` にルートを追加
5. `frontend/src/App.tsx` にルートを追加
6. `frontend/src/components/layout/AppLayout.tsx` の `NAV_ITEMS` にナビゲーションを追加
